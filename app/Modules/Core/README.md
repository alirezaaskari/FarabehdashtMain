# ماژول Core — زیرساخت‌های عرضی

## این ماژول چه می‌کند

کارهایی که همه ماژول‌های دیگر لازم دارند ولی هیچ‌کدام صاحبش نیستند: دفتر رویداد،
نسخه‌بندی محتوا، دسته‌بندی مشترک، تنظیمات مدیر، مدیا و لایه سئو.

## قاعده مهم این ماژول

Core ماژول **پایه** است: بقیه به آن تکیه می‌کنند، ولی **فقط از راه قراردادهای
`app/Contracts` و رویدادها**. هیچ ماژولی کلاس‌های `App\Modules\Core\Domain` را
import نمی‌کند — قاعده ۱ پروژه این‌جا هم استثنا ندارد.

به همین دلیل Core در `config/modules.php` بالاتر از بقیه می‌آید: ترتیب فهرست،
ترتیب ثبت ServiceProviderهاست.

## دفتر رویداد

قاعده ۷ پروژه: هر تغییر داده حساس یک Event منتشر می‌کند تا Audit Log مستقل بماند.

```php
// در ماژول شما — Core اصلاً دیده نمی‌شود
final readonly class ProfileApproved implements AuditableEvent
{
    public function auditEntry(): AuditEntry
    {
        return new AuditEntry(action: 'profile.approved', /* … */);
    }
}
```

Core روی **خود قرارداد** گوش می‌دهد، نه تک‌تک رویدادها؛ پس ماژول تازه برای
ثبت‌شدن در دفتر هیچ سیم‌کشی اضافه‌ای لازم ندارد. اگر Core غیرفعال باشد، رویداد
منتشر می‌شود و کسی به آن گوش نمی‌دهد — بدون خطا.

برای کاری که رویداد دامنه‌ای ندارد (ورود موفق، مشاهده اطلاعات تماس کارجو)
قرارداد `AuditTrail` مستقیم تزریق می‌شود. این استثناست، نه قاعده.

ردیف ثبت‌شده **هرگز** تغییر نمی‌کند: `update()` و `delete()` روی مدل `AuditLog`
خطا می‌دهند، نه اینکه فقط در قرارداد شفاهی ممنوع باشند.

## نسخه‌بندی محتوا

دفتر رویداد می‌گوید «چه کسی چه کاری کرد»؛ `content_revisions` می‌گوید «متن قبلی
چه بود». مدل، قرارداد `Revisable` را پیاده می‌کند و خودش تصمیم می‌گیرد چه
فیلدهایی ارزش نسخه‌برداری دارند — نه `view_count` و نه `updated_at`.

## دسته‌بندی مشترک

`health_domain`، `industry` و `content_type` روی مقاله، ابزار، دوره، محصول و
آگهی یکسان‌اند. فهرست دسته‌بندی‌های مجاز در `config/core.php` **بسته** است: اگر
هر ماژول بتواند دسته‌بندی تازه بسازد، شش ماه بعد پنج نام برای یک مفهوم داریم و
فیلتر مشترک سایت از کار می‌افتد.

## تنظیمات

`SettingsRepository` تنها راه خواندن و نوشتن تنظیمات مدیر است. مقدار JSON ذخیره
می‌شود تا نوع اصلی حفظ شود؛ تنظیمی که «true» و «۱» و «بله» را قاطی کند، دیر یا
زود یک کلید درآمدی را اشتباه خاموش می‌کند.

## سئو

| قطعه | کار |
| --- | --- |
| `App\Support\Seo\SeoMeta` | عنوان، توضیح، Canonical، noindex، تصویر و Schema یک صفحه |
| `App\Support\Seo\Schema` | سازنده داده ساختاریافته: Organization · WebSite · WebPage · Article · DefinedTerm · ChemicalSubstance · WebApplication · Course · Product · FAQ · Breadcrumb · `graph()` برای چند نوع در یک بلوک |
| `Seo/SitemapBuilder` | جمع‌کردن نشانی‌ها از ماژول‌ها به تفکیک بخش؛ بخش بزرگ‌تر از ۴۵٬۰۰۰ نشانی چند فایل می‌شود |
| `GET /sitemap.xml` | فهرست فایل‌های نقشه (sitemapindex)، کش‌شده |
| `GET /sitemap-{بخش}.xml` | نقشه یک بخش: `pages` · `encyclopedia` · `chemicals` · `tools` · `courses` · `shop` |
| `GET /robots.txt` | بیرون از production کاملاً بسته |

ماژول محتوایی برای آمدن در نقشه سایت، `SitemapSource` را پیاده می‌کند (نام
بخش + نشانی‌ها) و با برچسب `SitemapSource::TAG` در کانتینر ثبت می‌شود.
`SeoMeta` و `Schema` در بخش ۱۷ از Core به `app/Support/Seo` رفتند: ابزار
بی‌منطق مشترک‌اند و هر ماژولی بی‌آنکه Core را import کند صدایشان می‌زند.
`changefreq` و `priority` حذف شدند؛ گوگل هیچ‌کدام را نمی‌خواند.

`tests/Feature/PublicSeoTest.php` از نقشه سایت شروع می‌کند و هر نشانی را باز
می‌کند: ۲۰۰، بدون noindex، Canonical خودش، یک H1، توضیح، JSON-LD معتبر و
بدون ادعای اعتبار یا امتیاز (DEC-30).

دو قاعده که در کد اعمال شده‌اند:

- صفحه `noindex` هرگز `canonical` نمی‌دهد؛ دو پیام متناقض به موتور جست‌وجو.
- هیچ Schema اختراعی ساخته نمی‌شود و `Course` هرگز `accreditedBy` یا
  `educationalCredentialAwarded` ندارد — گواهی داخلی سایت مدرک رسمی نیست.

> **فایل ایستا مسیر را می‌بلعد.** وب‌سرور `public/robots.txt` را پیش از رسیدن به
> PHP جواب می‌دهد. لاراول یکی به‌صورت پیش‌فرض می‌سازد که همیشه «همه‌چیز آزاد»
> می‌گوید. آن فایل حذف شده و یک تست جلوی برگشتنش را می‌گیرد.

## وابستگی‌ها

هیچ ماژول دیگری.

## نقاط توسعه

- رابط مدیریتی تنظیمات، دفتر رویداد و مدیا — بخش ۵ (Filament).
- سرویس آپلود و تغییر اندازه تصویر روی `media_items`.
- هرس نسخه‌های قدیمی محتوا پس از یک بازه.
- `sitemapindex` وقتی تعداد نشانی‌ها از ۵۰٬۰۰۰ گذشت.

## حذف این ماژول

پوشه `app/Modules/Core` را حذف کنید و `'Core'` را از `config/modules.php`
بردارید. رویدادهای `AuditableEvent` همچنان منتشر می‌شوند و بی‌شنونده می‌مانند؛
نقشه سایت و robots هم دیگر مسیری ندارند.
