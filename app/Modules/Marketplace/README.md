# بازار پروژه — `Modules/Marketplace`

بخش ۲۱ نسخه ۴. کارفرما کار اندازه‌گیری، ارزیابی یا مستندسازی را تعریف می‌کند، مشاوران و
آزمایشگاه‌های تأییدشده پیشنهاد می‌دهند و پول هر مرحله تا تحویل در «امانت وجه پروژه»
می‌ماند. طرح کامل و تصمیم‌ها (DEC-75..90) در `/mnt/project-files/طرح-بخش-۲۱-نسخه-۴.md`.

نشانی عمومی `/market` است، چون `/projects` مال پروژه‌های اندازه‌گیری میزکار است.

## تعریف پروژه و فهرست عمومی (۲۱-۲)

```
کارفرما: SubmitProject::create/update → market_projects (در انتظار) + پیوست خصوصی
مدیر:    ReviewProject::approve → باز، published_at، bids_close_at = اکنون + مهلت پیشنهاد
         ReviewProject::reject(یادداشت) → برگشت برای اصلاح
کارفرما: CloseProject → بسته (فقط پیش از قرارداد)
```

- **DEC-76:** هر کاربر واردشده با موبایل تأییدشده (`mobile_verified_at`) پروژه تعریف می‌کند، نه فقط نقش کارفرمای کاریابی. همه پروژه‌ها پیش از انتشار تأیید مدیر می‌خواهند (توانایی `admin.market.review`، نقش مدیر محتوا).
- **DEC-87:** نوع کار همان ۱۲ خدمت ثابت دایرکتوری است و از قرارداد `ServiceProviderDirectory` (پیاده‌سازی در ماژول مشاوره) خوانده می‌شود. بی ماژول مشاوره فهرست خالی است و فرم پروژه نمی‌پذیرد.
- **DEC-79:** کمینه بودجه (۱ میلیون تومان) و مهلت پیشنهاد (۱۴ روز) در «قیمت‌ها و زمان‌ها» پنل‌اند (`MarketTunables`).
- **DEC-84:** نام کارفرما پیش‌فرض پنهان است و «کارفرما در اصفهان» می‌آید؛ با تیک «نمایش» نام شرکت دیده می‌شود.
- **DEC-90:** پروژه خصوصی در `/market`، صفحه‌های خدمت و شهر و نقشه سایت نمی‌آید و برای غریبه ۴۰۴ است.
- پروژه منتشرشده ویرایش نمی‌شود تا پیشنهادها روی متن دیگری نمانند؛ فقط بسته می‌شود.
- پیوست خصوصی روی دیسک `local` است. فقط کارفرما و دارنده `admin.market.review` دانلودش می‌کنند؛ بقیه ۴۰۴.
- سقف پروژه در انتظار یا باز هم‌زمان برای هر کارفرما: ۱۰.
- آگهی شغلی «پروژه‌ای» در میزکار کارفرما پیوند «این کار را در بازار پروژه تعریف کنید» دارد.

## پیشنهاد، گفت‌وگو و دعوت (۲۱-۳)

```
مجری:    SubmitBid::submit → market_bids (فعال) + اعلان به کارفرما؛ ویرایش تا انتخاب، withdraw → پس‌گرفته
دو طرف:  PostMessage → market_messages (رسیده یا نگه‌داشته طبق MessagePolicy)
مدیر:    ModerateMessage::approve → رسیده + اعلان به طرف مقابل
         ModerateMessage::reject → رد + یک اخطار (market_strikes)؛ با رسیدن به سقف، دسترسی بسته
         ManageMarketModeration::save(حالت، کلمه‌ها) · reopen(کاربر) → پاک‌شدن اخطارها
کارفرما: InviteProvider → market_invites + اعلان به مجری
```

- **DEC-77:** فقط دارنده `directory.listing.manage` (مشاور یا آزمایشگاه تأییدشده) پیشنهاد می‌دهد؛ نه روی پروژه خودش.
- **DEC-79:** ۱ تا ۵ مرحله، هر مرحله دست‌کم ۵۰۰ هزار تومان؛ هر دو تنظیم پنل‌اند. هر مجری روی هر پروژه یک پیشنهاد دارد.
- **DEC-86:** سقف ۳۰ پیشنهاد تازه در ۳۰ روز (تنظیم پنل). ویرایش پیشنهاد سقف را مصرف نمی‌کند.
- **DEC-80:** متن پیشنهاد و عنوان مرحله‌ها اگر راه تماس داشته باشد پذیرفته نمی‌شود. پیام گفت‌وگو در حالت «فقط مشکوک» (پیش‌فرض) فقط وقتی مشکوک است نگه داشته می‌شود و در حالت «همه پیام‌ها» همیشه. حالت و فهرست کلمه‌ها در `settings` (کلیدهای `MessagePolicy::MODE_KEY` و `WORDS_KEY`) و صفحه پنل «پیام‌های بازار» است؛ تغییر فقط روی پیام بعدی اثر دارد.
  - مشکوک: رشته ۷ رقم یا بیشتر (فارسی، عربی یا لاتین، با فاصله و خط تیره)، رقم با حروف، ایمیل (حتی `[at]`)، لینک یا شناسه `@`، یا کلمه‌ای از فهرست. تاریخ و مبلغ با «تومان/ریال/میلیون/هزار» مشکوک نیستند.
  - پیام نگه‌داشته فقط برای فرستنده دیده می‌شود؛ پیام ردشده هرگز به طرف مقابل نمی‌رسد.
  - هر رد یک اخطار است؛ با ۳ اخطار (تنظیم پنل) کاربر نه پیشنهاد می‌دهد نه پروژه تعریف می‌کند تا مدیر باز کند.
- **DEC-89:** دکمه «دعوت به پروژه» روی صفحه مشاور و آزمایشگاه (با `Route::has`). دعوت فقط روی پروژه باز خود کارفرما و برای ارائه‌دهنده منتشرشده در دایرکتوری.
- **DEC-90:** پروژه خصوصی را فقط دعوت‌شده‌ها می‌بینند و رویش پیشنهاد می‌دهند؛ اعلان «پروژه هم‌خدمت» برای پروژه خصوصی فرستاده نمی‌شود.
- پس از تأیید پروژه عمومی، ارائه‌دهنده‌های هم‌خدمت (و هم‌شهر، اگر پروژه شهر دارد) اعلان `marketplace.project_matched` می‌گیرند (`ServiceProviderDirectory::matching`).
- پیامک: پیشنهاد تازه، دعوت و بسته‌شدن دسترسی در گروه پیامک «بازار پروژه»؛ پیام گفت‌وگو فقط درون سایت.

## قرارداد و پرداخت مرحله‌ای (۲۱-۴)

```
کارفرما: AcceptBid → market_contracts (در انتظار پرداخت) + مرحله‌های منجمد؛ بقیه پیشنهادها بسته
کارفرما: MilestoneCheckout (درگاه یا کیف پول) → EscrowKeeper::hold(حساب «امانت وجه پروژه») → مرحله در امانت
مجری:    MilestoneFlow::deliver(توضیح + فایل) → تحویل‌شده، release_at = اکنون + ۷ روز
کارفرما: approve → EscrowKeeper::release (سهم مجری منهای کمیسیون) · requestRevision (حداکثر ۲ بار)
فرمان:   marketplace:sweep (ساعتی) → AcceptBid::lapse برای مرحله اول پرداخت‌نشده · MilestoneFlow::autoRelease
```

- **DEC-75:** نرخ کمیسیون جریان `project_market` (پیش‌فرض ۱۰٪، صفحه «نرخ کمیسیون») لحظه پذیرش روی قرارداد (`commission_bp`) ثبت می‌شود و فقط از سهم مجری برداشته می‌شود.
- **DEC-81:** مهلت پرداخت مرحله اول، آزادسازی خودکار و تعداد اصلاح تنظیم پنل‌اند. قرارداد پرداخت‌نشده بی‌اثر می‌شود، پیشنهادهای بسته‌شده دوباره فعال و پروژه با مهلت تازه باز.
- هر مرحله امانت جدای خودش را دارد (کلید `marketplace.milestone:{uuid}`)؛ بازگشت دوباره درگاه اثر مالی دوم ندارد. مرحله بعد فقط پس از آزادسازی مرحله قبل پرداخت می‌شود.
- کلید درآمدی `project_market_commission` فقط پذیرش پیشنهاد تازه را می‌بندد؛ پرداخت، تحویل و آزادسازی قرارداد جاری ادامه دارد تا پول امانی گیر نکند.
- پیوست خصوصی پروژه پس از پرداخت مرحله اول برای مجری باز می‌شود. فایل تحویل فقط برای دو طرف است.
- توضیح تحویل و اصلاح هم از `MessagePolicy` می‌گذرد؛ راه تماس پذیرفته نمی‌شود.
- پول آزادشده از همان «درخواست تسویه» موجود برداشت می‌شود (DEC-88).

## اعتراض، رأی مدیر و لغو (۲۱-۵)

```
هر طرف: ContractResolution::dispute(دلیل) → مرحله «اعتراض»؛ آزادسازی خودکار متوقف
مدیر مالی (پنل «اعتراض‌های بازار»): resolve → صفر به کارفرما = آزادسازی کامل، ادامه قرارداد
                                             همه به کارفرما = بازگشت کامل، پایان قرارداد
                                             بخشی = EscrowKeeper::split، پایان قرارداد
کارفرما: cancel (پیش از هر پرداخت) · requestCancel → مجری respondCancel(موافق/مخالف)
کارفرما: cancelOverdue → ۳ روز پس از مهلت تحویل مرحله، بازگشت کامل (DEC-83)
```

- **DEC-82:** هر بازگشت پول به کیف پول کارفرماست؛ کمیسیون فقط از بخش آزادشده برای مجری برداشته می‌شود.
- مرحله آزادشده هرگز برنمی‌گردد. رأی بازگشت کامل یا بخشی قرارداد را لغو و پروژه را می‌بندد.
- دلیل اعتراض هم از `MessagePolicy` می‌گذرد. فایل تحویل برای مدیر مالی هم باز است.
- مهلت لغو پس از گذشتن تاریخ تحویل (`cancel_grace_days`) در «قیمت‌ها و زمان‌ها» تنظیم می‌شود.

## امتیاز دوطرفه، سابقه مجری و گذرنامه (۲۱-۶)

- **DEC-85:** پس از پایان قرارداد (تمام‌شده، یا لغوشده پس از پرداخت دست‌کم یک مرحله) هر طرف یک بار ۱ تا ۵ و یک جمله کوتاه می‌دهد (`RateContract`).
  - امتیاز طرف دیگر پس از ثبت امتیاز خودتان یا گذشت `reveal_days` دیده می‌شود (`MarketRating::scopeRevealed`).
  - مهلت امتیاز، مهلت نمایش، کمینه میانگین و آستانه نشان کارفرما همه در «قیمت‌ها و زمان‌ها» تنظیم می‌شوند.
  - جمله امتیاز از `MessagePolicy` می‌گذرد. مدیر در پنل «امتیازهای بازار پروژه» فقط متن را پنهان می‌کند؛ عدد می‌ماند.
- `TrackRecord` قرارداد `ProjectTrackRecord` را پیاده می‌کند. صفحه عمومی مشاور و آزمایشگاه (ماژول مشاوره) از آن تعداد پروژه تحویل‌شده،
  میانگین (فقط با دست‌کم ۳ امتیاز) و چند جمله آخر را می‌گیرد. مقایسه پیشنهادها هم همین سابقه را کنار هر مجری نشان می‌دهد.
- `MarketEvidence` منبع گذرنامه مهارتی است: پروژه‌های تحویل‌شده به تفکیک نوع کار با برچسب `market-service:{key}`؛
  نگاشت به مهارت شغلی در `jobs.passport.tag_skills` است.
- نشان «کارفرمای خوش‌حساب در فرابهداشت» روی صفحه پروژه، برای کارفرمایی که چند قرارداد را تا آخر پرداخته. نشان داخلی است، نه مجوز.

## صفحه‌ها

| نشانی | کار |
|---|---|
| `/market` | فهرست پروژه‌های باز با پالایش نوع کار و شهر |
| `/market/service/{service}` | صفحه ثابت نوع کار |
| `/market/in/{city}` | صفحه ثابت شهر |
| `/market/{id}` | صفحه پروژه؛ فقط پروژه باز عمومی ایندکس می‌شود |
| `/workspace/market` | پروژه‌های من: ویرایش پیش از انتشار و بستن |
| `/workspace/market/new` | فرم تعریف پروژه با پیوست خصوصی |
| `/workspace/market/{uuid}` | پیشنهادهای یک پروژه کنار هم و دعوت‌شده‌ها |
| `/market/{id}/bid` | فرم پیشنهاد مجری با مرحله‌ها |
| `/market/invite/{provider}` | دعوت ارائه‌دهنده دایرکتوری به یکی از پروژه‌های باز |
| `/workspace/market/bids` | پیشنهادها و دعوت‌های مجری |
| `/workspace/market/bids/{uuid}` | پیشنهاد و گفت‌وگوی آن، مشترک کارفرما و مجری؛ دکمه پذیرش برای کارفرما |
| `/workspace/market/contracts/{uuid}` | قرارداد: پرداخت مرحله، تحویل، تأیید یا اصلاح، اعتراض، لغو و امتیاز |
| پنل «پروژه‌های بازار» | صف تأیید با توانایی `admin.market.review` |
| پنل «امتیازهای بازار پروژه» | پنهان کردن متن امتیاز با توانایی `admin.market.review` |
| پنل «اعتراض‌های بازار» | رأی اعتراض با توانایی `admin.refund.issue` (نقش مالی) |
| پنل «پیام‌های بازار» | کلید حالت بررسی، کلمه‌ها، صف پیام نگه‌داشته، باز کردن دسترسی |

پالایش فقط نوع کار یا فقط شهر به نشانی ثابت همان صفحه می‌رود و ترکیب پالایش‌ها noindex است.
صفحه نوع کار یا شهری که کمتر از دو پروژه باز دارد noindex است و در نقشه سایت نمی‌آید.

## وابستگی‌ها

- قراردادها: `ServiceProviderDirectory`، `EscrowKeeper`، `CommissionCalculator`، `SalesSwitch`، `PaymentGateway`، `SettingsStore`، `ApprovalQueueSource`، `SitemapSource`، `TunableSource`، `QuickActionSource`، `PassportEvidenceSource`؛ خودش `ProjectTrackRecord` را ثبت می‌کند.
- رویدادها: `ProjectSubmitted`، `ProjectReviewed`، `ProjectClosed`، `ProjectAnnounced`، `BidSubmitted`، `BidWithdrawn`، `MessagePosted`، `MessageModerated`، `MessagePolicyChanged`، `MarketAccessReopened`، `ProviderInvited`، `ContractChanged`، `ContractRated`، `RatingModerated`؛ همه `AuditableEvent` با شناسه، بی متن پیام.
