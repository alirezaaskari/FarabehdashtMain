# ماژول Identity — هویت و دسترسی

## این ماژول چه می‌کند

ورود و ثبت‌نام با شماره موبایل و رمز یک‌بارمصرف، نقش‌های تجاری به‌صورت پروفایل
روی همان یک حساب، و حل مجوزهای کاربر برای بقیه ماژول‌ها. ثبت‌نام جداگانه ندارد:
اولین ورود موفق با یک شماره، حساب را می‌سازد.

## قواعد محصول که این ماژول نگه می‌دارد

- یک حساب، چند پروفایل. نقش تازه، حساب تازه نمی‌سازد.
- هیچ پروفایل تجاری بدون تأیید مدیر فعال نمی‌شود؛ وضعیت اولیه همیشه
  `Pending` است، حتی اگر نقش قبلاً تأیید شده و کاربر خودش غیرفعالش کرده باشد.
- غیرفعال‌کردن پروفایل هیچ داده‌ای را حذف نمی‌کند؛ فقط دسترسی قطع می‌شود.
- مجوزها جمع‌شونده‌اند: مجوزهای پایه ∪ مجوزهای پروفایل‌های **فعال**.
- نقش مدیر از این مسیر فعال نمی‌شود.
- کد خام یک‌بارمصرف هرگز ذخیره نمی‌شود؛ فقط هش آن.
- کد ملی رمزنگاری‌شده ذخیره می‌شود و برای تشخیص تکراری، هش جداگانه دارد.

## ساختار

| مسیر | مسئولیت |
| --- | --- |
| `Domain/Enums` | `ProfileType` · `ProfileStatus` · `UserStatus` · `OtpPurpose` |
| `Domain` | `UserProfile` · `OtpCode` · `Exceptions/OtpException` |
| `Services/OtpService` | تولید، ارسال و بررسی کد؛ سه لایه محدودیت |
| `Services/PermissionResolver` | حل مجوزها و برچسب فارسی آن‌ها |
| `Services/Sms` | درایورهای `log` · `melipayamak` · `Fake` برای تست |
| `Actions` | ورود · درخواست فعال‌سازی · غیرفعال‌سازی · بررسی مدیر |
| `Http` | کنترلرها و FormRequestها |
| `routes/web.php` | مسیرهای ورود، خروج و پروفایل‌ها |

## وابستگی‌ها

هیچ ماژول دیگری. تنها قرارداد بیرونی، `App\Contracts\SmsSender` است که همین
ماژول پیاده‌سازی‌اش را به کانتینر می‌بندد.

مدل `App\Models\User` تنها استثنای قاعده «هیچ ماژولی مدل ماژول دیگر را import
نمی‌کند» است: User زیرساخت مشترک است، نه دارایی یک ماژول.

## پیکربندی

`config/identity.php` (با کلید `identity`):

| کلید | معنی |
| --- | --- |
| `otp.length` | طول کد |
| `otp.ttl_seconds` | اعتبار کد |
| `otp.resend_after_seconds` | فاصله تا ارسال بعدی |
| `otp.max_attempts` | تلاش نادرست تا سوختن کد |
| `otp.max_requests_per_hour` | سقف ساعتی هر شماره |
| `otp.max_requests_per_ip_per_hour` | سقف ساعتی هر IP |
| `sms.driver` | `log` یا `melipayamak` (متغیر `FBH_SMS_DRIVER`) |

> درایور `log` کد را در `storage/logs` می‌نویسد و در سطح **warning** ثبت می‌کند،
> نه `info`. رمز یک‌بارمصرفی که به‌جای پیامک در فایل می‌نشیند واقعاً وضعیت
> غیرعادی است؛ و با `info`، محیطی که `LOG_LEVEL=warning` دارد آن را بی‌صدا دور
> می‌ریخت و کسی نمی‌توانست وارد شود.
| `permissions.base` | مجوز هر کاربر احرازشده |
| `permissions.profiles` | مجوز هر نقش |
| `permissions.labels` | برچسب فارسی هر مجوز |

افزودن مجوز تازه به یک نقش فقط تغییر در همین فایل است؛ هر کلید به‌صورت خودکار
یک Gate می‌شود و با `$user->can('...')` یا `@can` بررسی می‌شود.

## نکته مسیرها

نام مسیر صفحه ورود `login` است، بدون پیشوند ماژول: فریم‌ورک و بسته‌هایش این را
نام قراردادی می‌دانند و میان‌افزار `auth` مهمان را به همان می‌فرستد. بقیه
مسیرها پیشوند `identity.` دارند.

## نقاط توسعه

- تکمیل پروفایل پایه (نام، کد ملی، استان) — بخش ۴.
- پنل مدیر برای صف بررسی پروفایل‌ها — بخش ۱۵.
- تغییر شماره موبایل با `OtpPurpose::MobileChange` (اینک فقط Enum آماده است).
- ورود با ایمیل و رمز عبور به‌عنوان مسیر دوم، در صورت نیاز.

## حذف این ماژول

پوشه `app/Modules/Identity` را حذف کنید و `'Identity'` را از `config/modules.php`
بردارید. چیدمان میزکار دکمه‌های «حساب من» و «خروج» را با `Route::has` می‌سنجد،
پس خودبه‌خود حذف می‌شوند.
