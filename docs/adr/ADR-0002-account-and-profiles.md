# ADR-0002 — مدل حساب ماژولار و نقش‌ها

- **وضعیت:** تأییدشده (تصمیم محصولی از پیش ثبت‌شده)

## تصمیم

هر انسان = **یک رکورد `users`**. هیچ حساب دومی ساخته نمی‌شود.
نقش پایه همه کاربران احرازشده `fbh_member` است.

نقش‌های تجاری به‌صورت **Profile** روی همان حساب فعال می‌شوند:

`jobseeker` · `employer` · `vendor` · `instructor` · `consultant`

هر Profile یک ردیف در `user_profiles` است با وضعیت مستقل
(`pending` → `active` → `suspended` / `disabled`).

## قواعد قطعی

1. فعال‌سازی هر Profile تجاری نیازمند **تأیید مدیر** است (حالت اولیه `pending`).
2. غیرفعال‌کردن Profile **هرگز داده را حذف نمی‌کند** — فقط دسترسی و نمایش را قطع می‌کند.
3. میزکار فقط بخش‌های مربوط به Profileهای `active` را نشان می‌دهد.
4. مجوزها جمع‌شونده‌اند: دسترسی کاربر = اتحاد مجوزهای پایه + مجوزهای Profileهای فعال.
5. `instructor` و `vendor` یک هویت مالی مشترک دارند (یک کیف پول، یک تسویه) — مدرس
   زیرمجموعه فروشنده است، نه یک موجودیت مالی جدا.
6. نقش `admin` از مسیر Profile فعال نمی‌شود؛ فقط توسط مدیر ارشد و با Audit Log.

## حریم خصوصی کارجو (قاعده غیرقابل نقض)

- شماره تماس، ایمیل، کد ملی و آدرس دقیق کارجو بدون **اجازه صریح و ثبت‌شده** او به
  کارفرما یا عموم نمایش داده نمی‌شود.
- حضور در بانک رزومه **Opt-in صریح** است و پیش‌فرض آن خاموش است.
- کارجو **هرگز** برای دیدن آگهی یا ارسال درخواست پول نمی‌دهد.
- هر بار افشای اطلاعات تماس به یک کارفرما یک ردیف در `resume_access_logs` ثبت می‌کند.

## احراز هویت

ورود با **موبایل + OTP** (ملی‌پیامک). رمز عبور اختیاری و ثانویه است.
کدها فقط به‌صورت Hash ذخیره می‌شوند، با انقضا، سقف تلاش و محدودیت نرخ ارسال.

## بررسی‌های عملی انجام‌شده هنگام پیاده‌سازی بخش ۳

### لایه مجوز بومی به‌جای `spatie/laravel-permission`

بسته Spatie روی مدل «کاربر ← نقش ← مجوز» بنا شده و نقش را یک برچسب روی کاربر
می‌داند. مدل ما این نیست: نقش این‌جا یک **ردیف با وضعیت** است (`pending`،
`active`، `suspended`، `disabled`) و فقط ردیف `active` مجوز می‌دهد. پیاده‌سازی
همین رفتار با Spatie یعنی همگام‌نگه‌داشتن دستی جدول نقش‌های آن بسته با جدول
`user_profiles` — دو منبع حقیقت برای یک چیز.

`PermissionResolver` همین منطق را در یک کلاس کوچک می‌نویسد: مجوزهای پایه ∪
مجوزهای پروفایل‌های فعال. نگاشت مجوز به نقش در `config/identity.php` است، پس
افزودن مجوز تازه تغییر کد ندارد و هر کلید خودکار یک Gate لاراول می‌شود.

> نکته محیطی: دانلود بسته‌ها از GitHub در محیط ساخت این بخش مسدود بود. این
> محدودیت **دلیل** تصمیم نبود — دلیلش ناهم‌خوانی مدل داده است — ولی صادقانه ثبت
> می‌شود که فرصت آزمودن عملی بسته Spatie هم وجود نداشت.

### شماره موبایل به‌عنوان Value Object

`App\Support\Mobile` هر شکل نوشتن یک شماره (`۰۹۱۲…`، `+۹۸۹۱۲…`، `0098912…`،
`9121234567`، با فاصله و خط تیره، با ارقام فارسی یا عربی) را به یک قالب قطعی
`09xxxxxxxxx` می‌رساند. بدون این، یک کاربر با دو حساب تکراری تمام می‌شد.

### کد ملی

ستون `national_code` رمزنگاری‌شده ذخیره می‌شود، پس روی خودش ایندکس یکتا ممکن
نیست. برای تشخیص تکراری، ستون جداگانه `national_code_hash` با ایندکس یکتا
نگه داشته می‌شود.

### استثنای قاعده «هیچ ماژولی مدل ماژول دیگر را import نمی‌کند»

`App\Models\User` بیرون از ماژول‌ها می‌ماند و همه ماژول‌ها مستقیم از آن استفاده
می‌کنند. User زیرساخت مشترک است، نه دارایی یک ماژول؛ بردنش داخل `Identity` یعنی
هر ماژول دیگری به `Identity` وابسته می‌شود و هدف جداسازی از بین می‌رود.
این تنها استثناست و جای دیگری تکرار نمی‌شود.
