# ADR-0002 — مدل حساب ماژولار و نقش‌ها

- **وضعیت:** تأییدشده (تصمیم محصولی از پیش ثبت‌شده)

## تصمیم

هر انسان = **یک رکورد `users`**. هیچ حساب دومی ساخته نمی‌شود.
نقش پایه همه کاربران احرازشده `fbh_member` است.

نقش‌های تجاری به‌صورت **Profile** روی همان حساب فعال می‌شوند:

`jobseeker` · `employer` · `vendor` · `instructor` · `consultant`

هر Profile یک ردیف در `user_profiles` است با وضعیت مستقل
(`pending` → `active` → `suspended` / `disabled`).

## قواعد قطعی

1. فعال‌سازی هر Profile تجاری نیازمند **تأیید مدیر** است (حالت اولیه `pending`).
2. غیرفعال‌کردن Profile **هرگز داده را حذف نمی‌کند** — فقط دسترسی و نمایش را قطع می‌کند.
3. میزکار فقط بخش‌های مربوط به Profileهای `active` را نشان می‌دهد.
4. مجوزها جمع‌شونده‌اند: دسترسی کاربر = اتحاد مجوزهای پایه + مجوزهای Profileهای فعال.
5. `instructor` و `vendor` یک هویت مالی مشترک دارند (یک کیف پول، یک تسویه) — مدرس
   زیرمجموعه فروشنده است، نه یک موجودیت مالی جدا.
6. نقش `admin` از مسیر Profile فعال نمی‌شود؛ فقط توسط مدیر ارشد و با Audit Log.

## حریم خصوصی کارجو (قاعده غیرقابل نقض)

- شماره تماس، ایمیل، کد ملی و آدرس دقیق کارجو بدون **اجازه صریح و ثبت‌شده** او به
  کارفرما یا عموم نمایش داده نمی‌شود.
- حضور در بانک رزومه **Opt-in صریح** است و پیش‌فرض آن خاموش است.
- کارجو **هرگز** برای دیدن آگهی یا ارسال درخواست پول نمی‌دهد.
- هر بار افشای اطلاعات تماس به یک کارفرما یک ردیف در `resume_access_logs` ثبت می‌کند.

## احراز هویت

ورود با **موبایل + OTP** (ملی‌پیامک). رمز عبور اختیاری و ثانویه است.
کدها فقط به‌صورت Hash ذخیره می‌شوند، با انقضا، سقف تلاش و محدودیت نرخ ارسال.
